Contiene las definiciones de las tablas PostgreSQL mediante **Drizzle ORM**. Usa **un archivo por tabla** con el nombre de la tabla y el sufijo `.table.ts`.

## Campos obligatorios en absolutamente todas las tablas

**Regla indispensable y sin excepciones:** cada tabla definida en `src/db/tables` debe incluir **exactamente estos tres campos de auditoría**, siempre con sus nombres de propiedad y de columna **en inglés**, incluso en tablas intermedias o de relaciones.

```typescript nombre-tabla.table.ts
createdAt: timestamp('created_at').defaultNow().notNull(),
updatedAt: timestamp('updated_at').defaultNow().notNull(),
deletedAt: timestamp('deleted_at'),
```

| Campo | Función |
| --- | --- |
| `createdAt` / `created_at` | Fecha y hora en que se crea el registro. |
| `updatedAt` / `updated_at` | Fecha y hora de su última actualización. |
| `deletedAt` / `deleted_at` | Marca de eliminación lógica (_soft delete_); permanece `null` mientras el registro está activo. |

No los traduzcas a `creadoEn`, `actualizadoEn` o `eliminadoEn`, ni omitas ninguno al crear una tabla nueva.

**Importante:** `defaultNow()` establece el valor inicial de `updatedAt`, pero **no lo actualiza automáticamente** cuando cambia el registro. La lógica de actualización debe asignar `updatedAt: new Date()` (o configurarse explícitamente para hacerlo).

## Ejemplo de estructura

```text src/db/tables
tables/
├── user.table.ts
├── category.table.ts
└── product.table.ts
```

## Ejemplo completo

```typescript user.table.ts
import { pgTable, serial, text, varchar, timestamp, pgEnum, index, uniqueIndex } from 'drizzle-orm/pg-core';
import { sql } from 'drizzle-orm';

const userRoleEnum = pgEnum('user_role', ['admin', 'employee', 'viewer']);

export const user = pgTable(
  'user',
  {
    id: serial('id').primaryKey(),
    createdAt: timestamp('created_at').defaultNow().notNull(),
    updatedAt: timestamp('updated_at').defaultNow().notNull(),
    deletedAt: timestamp('deleted_at'),
    email: varchar('email', { length: 255 }).notNull(),
    password: text('password').notNull(),
    firstName: varchar('first_name', { length: 100 }).notNull(),
    lastName: varchar('last_name', { length: 100 }).notNull(),
    fullName: varchar('full_name', { length: 200 }).notNull(),
    role: userRoleEnum('role').default('viewer').notNull(),
    isActive: varchar('is_active', { length: 10 }).default('true').notNull(),
  },
  (t) => [
    // Search indexes
    index('user_full_name_idx').using('gin', t.fullName.op('gin_trgm_ops')),
    index('user_email_idx').on(t.email),
    index('user_created_at_idx').on(t.createdAt),

    // Unique partial indexes (Soft Delete)
    uniqueIndex('user_email_unique_active_idx')
      .on(t.email)
      .where(sql`${t.deletedAt} IS NULL`),
  ],
);

export type User = typeof user.$inferSelect;
export type UserDTO = typeof user.$inferInsert;
```

## Convenciones de nombres y exportaciones

| Elemento | Convención | Ejemplo |
| --- | --- | --- |
| Archivo | Nombre de tabla + `.table.ts` | `user.table.ts` |
| Tabla Drizzle | Exportar la definición para poder utilizarla desde queries y conexiones | `export const user` |
| Enum interno | Nombre de tabla + columna + `Enum`; declararlo en el mismo archivo **sin exportarlo** | `const userRoleEnum` |
| Tipo SELECT | Nombre de entidad | `export type User` |
| Tipo INSERT | Nombre de entidad + `DTO` | `export type UserDTO` |

Los enums exclusivos de una tabla **se definen dentro de su archivo y no se exportan**. Sí se exportan la tabla y sus dos tipos inferidos por Drizzle: `$inferSelect` para lectura y `$inferInsert` para inserción. Los DTO deben obtener los valores del enum desde la columna exportada: `user.role.enumValues` (para Swagger, `@IsEnum` y el tipo TypeScript), sin crear otro enum ni duplicar sus valores. Si un enum necesitara compartirse entre varias tablas, habría que diseñar una definición común.

**Nota:** el índice GIN con `gin_trgm_ops` requiere habilitar la extensión `pg_trgm` en PostgreSQL.
