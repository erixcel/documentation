Cada archivo `*.seed.ts` contiene la **carga inicial de una sola tabla**. El nombre debe corresponder a la tabla: `categoria.seed.ts`, `producto.seed.ts`, etc. En `src/seeds/` **solo se permiten archivos `.seed.ts` en el nivel raíz**: no puede haber JSON, TypeScript auxiliar ni subcarpetas, incluyendo `data/`.

## Estructura

```text src/seeds
seeds/
├── categoria.seed.ts
├── producto.seed.ts
├── usuario.seed.ts
└── cliente.seed.ts
```

## Convenciones

| Elemento | Regla |
| --- | --- |
| Archivo | Un `nombre-tabla.seed.ts` por tabla. |
| Función | Exactamente una función exportada `seedNombre(...)`, por ejemplo `seedCategorias()`; puede ser `async`. No se permiten clases ni funciones adicionales. |
| Estructura | Solo imports y una función exportada. No declarar `type`, `interface`, `const`, `let` o funciones sueltas a nivel superior; tampoco `type` o `interface` dentro del seed. Constantes y datos pueden declararse **dentro** de la función. |
| Datos | JSON u objetos iniciales incorporados a la función del seed que los inserta; no guardarlos en `seeds/data/` ni importarlos desde un archivo de datos local. |
| Trazabilidad | Los seeds **no requieren** TraceFlow ni `@TraceNode`. |
| Operación | Insertar los datos iniciales con Drizzle ORM en una única tabla base. |
| Retorno | Puede devolver los registros insertados para que los utilicen otros seeds. |
| Orden | Ejecutar primero tablas independientes, y después las que necesitan claves foráneas. |

## Ejemplo: JSON integrado en el seed

Cuando exista `src/seeds/data/fija-matches.json`, **primero traslada los registros** a la función `seedFijaMatches()` de `src/seeds/fija-matches.seed.ts`. Comprueba contenido, referencias e idempotencia antes de eliminar el JSON anterior. Estos seeds no necesitan TraceFlow.

```typescript fija-matches.seed.ts
import { database } from '@db/connection.db';
import { fijaMatches } from '@db/tables/fija-matches.table';

export async function seedFijaMatches() {
  const records = [
    {
      predictions: ['Gana Universitario', 'Más de 1.5 goles'],
      odds: '2.10',
      fijaId: '20000000-0000-4000-8000-000000000001',
      position: 0,
      leagueApiId: 281,
    },
  ];
  return database.insert(fijaMatches).values(records).onConflictDoNothing();
}
```

El ejemplo es ilustrativo: añade los campos obligatorios reales de tu esquema. Usa `import type` cuando se necesiten tipos externos, sin declarar `type` ni `interface` en el seed.

## Validación automática de carpetas

**Detect Changes** registra todas las modificaciones dentro de `src/seeds/`, incluso cambios de JSON, carpetas nuevas vacías y eliminaciones. Al terminar Codex, **Seed Validator** revisa la estructura completa y los archivos de seed aunque ningún `*.seed.ts` haya sido editado directamente. Si encuentra algo no permitido, devuelve instrucciones a Codex para corregirlo. **El Hook no elimina datos ni ejecuta la base de datos por sí mismo.**

Puedes ejecutar la validación manual de la carpeta:

```bash Terminal
python3 ~/.codex/plugins/cache/erixcel-tools/nestjs-standards/1.10.0/hooks/validate-seed.py --check backend/src/seeds
```

La ruta exacta depende de la versión instalada del plugin.

## Ejecución centralizada

`src/db/seed.db.ts` importa y ejecuta estos archivos en orden:

```typescript seed.db.ts
const categorias = await seedCategorias();
await seedProductos(categorias);
```

```bash Terminal
npm run db:seed
```

**Importante:** estos ejemplos no evitan inserciones duplicadas si se ejecutan varias veces. Para que sean idempotentes, aplica restricciones únicas y estrategias como `onConflictDoNothing()` cuando corresponda.

## Ejemplo: `categoria.seed.ts`

Carga datos iniciales de la **tabla categorías**, sin insertar registros de otras tablas.

```typescript categoria.seed.ts
import { database } from '@db/connection.db';
import { categorias } from '@db/tables/categoria.table';

export async function seedCategorias() {
  console.log('🌱 Cargando categorías...');

  const registros = await database
    .insert(categorias)
    .values([
      { nombre: 'Tecnología' },
      { nombre: 'Hogar' },
    ])
    .returning();

  console.log('✅ Categorías cargadas.');
  return registros;
}
```

Devuelve los registros insertados con sus IDs para que otros seeds puedan utilizar sus relaciones. Adapta los campos al esquema real.

## Ejemplo: `producto.seed.ts`

Carga productos utilizando el ID de una categoría **previamente insertada**. La función recibe los datos del seed de categorías para respetar la clave foránea.

```typescript producto.seed.ts
import { database } from '@db/connection.db';
import { productos } from '@db/tables/producto.table';

export async function seedProductos(categorias: { id: number; nombre: string }[]) {
  console.log('🌱 Cargando productos...');

  const categoria = categorias.find((item) => item.nombre === 'Hogar');

  if (!categoria) {
    throw new Error('No se encontró la categoría Hogar.');
  }

  const registros = await database
    .insert(productos)
    .values([
      { nombre: 'Lámpara', categoriaId: categoria.id },
      { nombre: 'Escritorio', categoriaId: categoria.id },
    ])
    .returning();

  console.log('✅ Productos cargados.');
  return registros;
}
```

En `src/db/seed.db.ts` ejecútalos en orden:

```typescript seed.db.ts
const categorias = await seedCategorias();
await seedProductos(categorias);
```

Cada archivo seed debe insertar **solo la tabla a la que pertenece**. Los campos son de ejemplo y deben adaptarse al esquema real.
