# Erixcel React: estructura

Esta guía es la **fuente de verdad** para el plugin React 19 + Vite 8 + TypeScript. No se aplican convenciones de NestJS a este frontend.

```text
frontend/
├── src/
│   ├── api/
│   │   └── backend.api.ts          # Generado desde el backend
│   ├── assets/
│   ├── components/
│   │   ├── simple/
│   │   └── complex/
│   ├── hooks/                      # *.hook.ts
│   ├── pages/                      # Por funcionalidad
│   ├── routes/                     # Solo configuración
│   ├── services/                   # *.service.ts
│   ├── index.css                   # Tailwind + @theme
│   └── main.tsx
├── .env
├── .env.example
└── package.json
```

## Reglas verificables

| Área | Convención |
| --- | --- |
| CSS | Solo `src/index.css` propio; `@import 'tailwindcss';` y tokens `@theme`, sin selectores ni reglas propias |
| API | Solo `src/api/backend.api.ts` generado; no modificar a mano |
| Componentes | `simple/` y `complex/`; simples planos, complejos por carpeta |
| Hooks | Todos los hooks en `*.hook.ts`; solo imports y funciones a nivel superior |
| Servicios | Todos los servicios en `*.service.ts`; solo imports y funciones a nivel superior |
| Módulos | Funcionalidades por carpeta, incluyendo `not-found/` |
| Rutas | Configuración en `src/routes/`; páginas en `src/pages/` |
| Entrada | `createRoot`, `RouterProvider` y `index.css` desde `main.tsx` |

Los archivos técnicos de Vite, ESLint, TypeScript y despliegue en la raíz **siguen permitidos**. `package.json` y la estructura general se documentan como referencias flexibles; **ya no los bloquean los Hooks**. Las variables `.env` y `.env.example` mantienen su validador específico de seguridad.

## Hooks de validación

`Detect Changes` en `UserPromptSubmit` almacena hashes y rutas, no contenidos ni secretos. Al concluir, los **siete validadores `Stop` activos** inspeccionan cambios de las áreas que supervisan. **No se ejecutan validadores de estructura general, páginas/rutas ni `package.json`**; estas reglas permanecen como orientaciones para la IA. En archivos de hooks/servicios usan el **AST de TypeScript** para reconocer declaraciones y reportar archivo y línea sin confundir comentarios o strings. El Hook devuelve feedback para que Codex se autocorrija; **no modifica ni borra archivos**.

## Decisiones pendientes

La ubicación/nomenclatura oficial de contratos de tipos y de estado compartido todavía no está acordada. No inventes carpetas, no reemplaces tipos por `any` y no destruyas cachés o sesiones existentes para cumplir la regla. Tampoco existe un mecanismo de procedencia para distinguir un cambio manual a `backend.api.ts` de una regeneración legítima: el Hook valida la estructura y la Skill indica regenerarlo desde el backend.

Consulta cada carpeta para ejemplos de código y excepciones.
