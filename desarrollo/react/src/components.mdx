# src/components

Solo pueden existir `simple/` y `complex/` en la raíz de componentes compartidos:

```text
src/components/
├── simple/
│   ├── button.component.tsx
│   └── input.component.tsx
└── complex/
    └── audio-recorder/
        ├── audio-recorder.component.tsx
        ├── hooks/
        │   └── audio-recorder.hook.ts
        └── services/
            └── audio-recorder.service.ts # Solo cuando se necesita
```

## Simple

Solo archivos planos `*.component.tsx`, sin carpetas ni barrels `index.ts`. Son componentes de presentación controlados mediante props. Se permiten callbacks como onClick/onChange y `useId` para accesibilidad. No gestionan HTTP, almacenamiento, grabaciones, suscripciones ni procesos propios.

## Complex

Cada componente tiene una carpeta con vista `nombre.component.tsx` y las subcarpetas `hooks/` y `services/`. La lógica React se mantiene en hooks, y las operaciones independientes en servicios. No crees archivos o funciones vacíos: un componente puede requerir un hook y ningún servicio.

La vista conecta eventos con la lógica, sin duplicar responsabilidades. Los imports de componentes compartidos apuntan al archivo directamente, **sin barrels**. Las reglas `*.hook.ts` y `*.service.ts` también se aplican a los archivos internos.

**Component Validator** comprueba estructura y nombres y detecta llamadas HTTP directas en componentes compartidos. No restaures el formato antiguo de archivos planos para componentes complejos.
