# Services

Los archivos en `src/services/` y en servicios privados de páginas o componentes complejos deben terminar en `*.service.ts`.

```text
src/services/upload-attachment.service.ts
src/pages/auth/services/auth-session.service.ts
src/components/complex/toast/services/toast.service.ts
```

Los servicios realizan operaciones de API, almacenamiento y transformación. Obtienen sus clientes o sesiones **desde stores**, mediante accessors como `getApi()`, `getAdminApi()` o `getAdminSession()` que devuelven la misma instancia; no construyen una nueva en cada llamada. Consulta [stores](/desarrollo/react/src/stores). En el nivel superior **solo imports y funciones**, incluidas expresiones/arrow functions asignadas a `const`. Se permiten múltiples funciones y variables locales con tipos inline y genéricos.

Prohibidos a nivel superior: `type`, `interface`, `class`, `enum`, `namespace`, instancias, constantes de datos, cachés, sesiones compartidas o ejecución al importar. Prohibidos JSX, ReactDOM, hooks React y `@Injectable` de NestJS.

```ts src/services/health.service.ts
export async function loadHealth(): Promise<{ status: string }> {
  const response = await fetch(import.meta.env.VITE_API_URL + '/health');
  if (!response.ok) throw new Error('No se pudo consultar el estado');
  return response.json();
}
```

Esto es un ejemplo ilustrativo. Si el proyecto dispone de operaciones generadas en `backend.api.ts`, consúmelas conservando las firmas reales. No inventes rutas ni elimines el estado compartido; **los contratos reutilizables mantienen una ubicación pendiente, pero las sesiones compartidas ahora pertenecen a stores**.

**Service Validator** usa AST para verificar las declaraciones y rechazar React Hooks, JSX y ReactDOM; en Vite usa `import.meta.env`, no `process.env`.

## Cliente ya inicializado

```ts src/pages/admin/services/admin-client.service.ts
import { getAdminApi } from '../stores/admin-client.store';

export function getAdminClient() {
  return getAdminApi(); // Devuelve la instancia existente.
}
```

Mantén separadas la sesión administrativa y la del apostador. Un 401 de administración no cierra la sesión del apostador, y una respuesta antigua no elimina una sesión renovada. Estas propiedades exigen **pruebas de comportamiento**: el AST no puede garantizarlas.
