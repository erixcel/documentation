Linux is the backbone of modern software development — servers, containers, CI/CD pipelines, and cloud infrastructure all run on it. Mastering the command line isn't optional; it's what separates developers who are productive on any machine from those who are lost without a GUI. This reference covers the commands you'll reach for every single day.

---

## Navegación y Archivos

Getting around the filesystem and managing files efficiently is the foundation of everything else.

```bash
# List files (simple)
ls

# List all files including hidden, with permissions and sizes
ls -la

# List sorted by modification time, newest first
ls -lt

# Change directory
cd /var/log
cd ~          # Go to home directory
cd -          # Go to previous directory

# Print working directory
pwd

# Create nested directories in one shot
mkdir -p projects/myapp/src/utils

# Remove directory and all contents (no confirmation!)
rm -rf dist/

# Remove a single file
rm file.txt

# Copy file or directory
cp file.txt file.bak
cp -r src/ src_backup/

# Move or rename
mv old-name.txt new-name.txt
mv file.txt /tmp/

# Find files by name, type, or size
find . -name "*.log" -type f
find /var -name "*.conf" -mtime -7      # Modified in last 7 days
find . -size +100M                       # Files larger than 100 MB
find . -name "*.js" -not -path "*/node_modules/*"

# Locate a file using the system index (faster than find)
locate nginx.conf
sudo updatedb    # Refresh the index first

# Show full path of a command
which python3
which node

# Identify file type
file mystery-file

# Detailed file metadata
stat README.md
```

<Tip>
  **Power trick:** Combine `find` with `-exec` to act on results directly:
  ```bash
  # Delete all .DS_Store files recursively
  find . -name ".DS_Store" -exec rm {} \;

  # Change permissions on all .sh files
  find . -name "*.sh" -exec chmod +x {} \;
  ```
</Tip>

## Permisos

Linux permissions control who can read, write, and execute files. Understanding them is essential for security and for running scripts or services correctly.

```bash
# Change file permissions (symbolic)
chmod +x script.sh          # Add execute for everyone
chmod u+x,g-w file.txt      # Add execute for user, remove write for group
chmod a-x file.txt          # Remove execute for all

# Change file permissions (numeric / octal)
chmod 755 script.sh   # rwxr-xr-x  — owner: rwx, group: r-x, others: r-x
chmod 644 config.txt  # rw-r--r--  — owner: rw, group: r, others: r
chmod 600 id_rsa      # rw-------  — owner only (ideal for SSH keys)
chmod 777 /tmp/share  # rwxrwxrwx  — everyone (use sparingly!)

# Numeric permission reference:
# 4 = read (r)
# 2 = write (w)
# 1 = execute (x)
# Sum them: 7=rwx, 6=rw-, 5=r-x, 4=r--

# Change file owner
chown alice file.txt
chown alice:developers file.txt    # Change owner AND group
chown -R alice:alice /var/app      # Recursively

# Change group only
chgrp www-data /var/www/html

# Run a command as superuser
sudo apt update
sudo systemctl restart nginx

# Switch to root shell (use with care)
sudo -i

# Switch to another user
su - bob
```

<Tip>
  **Check permissions at a glance:** `ls -l` shows permissions in the format `-rwxr-xr-x`. The first character is the type (`-` file, `d` directory, `l` symlink). The next 9 characters are owner/group/others permissions in groups of 3.
</Tip>

## Procesos

Understanding what's running on your system — and how to control it — is critical for debugging and performance troubleshooting.

```bash
# Show all running processes (snapshot)
ps aux

# Filter processes by name
ps aux | grep nginx

# Interactive process viewer
top

# Better interactive viewer (install if needed: apt install htop)
htop

# Kill a process by PID
kill 1234
kill -9 1234    # Force kill (SIGKILL) — use when regular kill doesn't work

# Kill all processes matching a name
killall node
killall -9 python3

# Kill processes matching a pattern
pkill -f "gunicorn"

# Run a command in the background
./long-running-script.sh &

# List background jobs
jobs

# Bring a background job to the foreground
fg %1

# Send a foreground job to background
# (first press Ctrl+Z to suspend, then:)
bg %1

# Run a command immune to hangups (survives terminal close)
nohup ./server.sh > server.log 2>&1 &

# Check PID of a named process
pgrep nginx
pidof apache2
```

<Tip>
  **Quick kill by port:** If a process is blocking a port, find and kill it in one pipeline:
  ```bash
  kill -9 $(lsof -t -i:3000)
  ```
  Or with `fuser`:
  ```bash
  fuser -k 3000/tcp
  ```
</Tip>

## Red

Networking commands for testing connectivity, inspecting ports, and transferring data.

```bash
# Test connectivity
ping google.com
ping -c 4 8.8.8.8    # Send exactly 4 packets

# Make HTTP requests (essential for API testing)
curl https://api.example.com/health
curl -X POST https://api.example.com/data \
  -H "Content-Type: application/json" \
  -d '{"key": "value"}'
curl -o output.html https://example.com    # Save to file
curl -I https://example.com               # Headers only
curl -u user:pass https://api.example.com # Basic auth
curl -s https://api.example.com | jq .    # Pipe into jq for pretty JSON

# Download files
wget https://example.com/file.tar.gz
wget -O custom-name.tar.gz https://example.com/file.tar.gz
wget -q --show-progress https://example.com/large-file.iso

# Show active connections and listening ports (legacy)
netstat -tulnp     # TCP/UDP listening ports with PIDs

# Modern replacement for netstat
ss -tulnp          # Same but faster
ss -s              # Summary statistics

# List processes using network connections
lsof -i             # All network connections
lsof -i :80         # Who is using port 80?
lsof -i tcp         # TCP connections only

# Trace the route packets take
traceroute google.com

# DNS lookup
dig google.com
dig google.com MX          # Mail exchange records
dig @8.8.8.8 google.com   # Use specific DNS server

# Another DNS lookup tool
nslookup google.com

# Show network interfaces (legacy)
ifconfig

# Modern replacement
ip addr
ip addr show eth0
ip route show          # Routing table
```

<Tip>
  **Combine `curl` with `jq` for slick API debugging:**
  ```bash
  curl -s "https://api.github.com/users/torvalds" | jq '.name, .public_repos'
  ```
  Install `jq` with `apt install jq` or `brew install jq`.
</Tip>

## Texto y Búsqueda

Linux shines at text processing. These tools let you search, filter, transform, and analyze text data without writing a single line of Python.

```bash
# Search for a pattern in a file
grep "ERROR" app.log
grep -i "error" app.log        # Case-insensitive
grep -n "ERROR" app.log        # Show line numbers
grep -c "ERROR" app.log        # Count matches
grep -v "DEBUG" app.log        # Invert match (exclude DEBUG lines)

# Search recursively in directories
grep -r "TODO" src/
grep -rl "password" .          # Only show filenames with matches

# Extended regex (ERE)
grep -E "ERROR|WARN|FATAL" app.log
grep -E "^[0-9]{4}-[0-9]{2}" app.log    # Lines starting with a date

# Powerful text processing with awk
awk '{print $1}' access.log                   # Print first column
awk -F: '{print $1}' /etc/passwd              # Use : as delimiter
awk '$3 > 1000 {print $1, $3}' /etc/passwd   # Conditional print
awk '{sum += $5} END {print sum}' data.txt    # Sum column 5

# Stream editor for substitutions
sed 's/foo/bar/' file.txt            # Replace first occurrence per line
sed 's/foo/bar/g' file.txt           # Replace all occurrences
sed -i 's/foo/bar/g' file.txt        # Edit file in place
sed -n '10,20p' file.txt             # Print lines 10-20
sed '/^#/d' config.txt               # Delete comment lines

# Display file contents
cat file.txt
cat -n file.txt       # With line numbers
cat a.txt b.txt > combined.txt

# Page through long output
less app.log          # Navigate with arrow keys, / to search, q to quit
more app.log          # Simpler pager

# Show first/last N lines
head -n 20 app.log
tail -n 50 app.log

# Follow a log file in real time
tail -f /var/log/nginx/access.log

# Follow multiple files
tail -f /var/log/nginx/access.log /var/log/nginx/error.log

# Word, line, character counts
wc -l file.txt     # Line count
wc -w file.txt     # Word count
wc -c file.txt     # Byte count

# Sort lines
sort names.txt
sort -r names.txt          # Reverse
sort -n numbers.txt        # Numeric sort
sort -k2 -t, data.csv      # Sort by column 2, comma-delimited

# Remove duplicate adjacent lines (sort first!)
sort data.txt | uniq
sort data.txt | uniq -c    # Count occurrences
sort data.txt | uniq -d    # Show only duplicates

# Extract fields/columns
cut -d: -f1 /etc/passwd         # First field, colon-delimited
cut -d, -f1,3 data.csv          # Fields 1 and 3
cut -c1-10 file.txt             # Characters 1–10
```

<Tip>
  **Real-time log analysis pipeline:** Combine these tools for powerful one-liners:
  ```bash
  # Top 10 IP addresses hitting your web server
  awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

  # Count HTTP status codes
  awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn
  ```
</Tip>

## Compresión

```bash
# Create a tar.gz archive
tar czf archive.tar.gz directory/
tar czf backup-$(date +%Y%m%d).tar.gz /var/app

# Extract a tar.gz archive
tar xzf archive.tar.gz
tar xzf archive.tar.gz -C /tmp/    # Extract to specific directory

# List contents of archive without extracting
tar tzf archive.tar.gz

# Create a tar.bz2 archive (better compression, slower)
tar cjf archive.tar.bz2 directory/

# Extract tar.bz2
tar xjf archive.tar.bz2

# Create and extract .zip
zip -r archive.zip directory/
zip archive.zip file1.txt file2.txt
unzip archive.zip
unzip archive.zip -d /tmp/extracted/

# List zip contents
unzip -l archive.zip

# Compress a single file
gzip largefile.log         # Replaces file with largefile.log.gz
gzip -k largefile.log      # Keep the original

# Decompress
gunzip largefile.log.gz

# Compress with best compression ratio
gzip -9 file.txt
```

<Tip>
  **Mnemonic for `tar` flags:** **c**reate, e**x**tract, **z**ip (gzip), **f**ile — so `czf` = create gzip file, `xzf` = extract gzip file. Add `v` for **v**erbose output to see each file as it's processed.
</Tip>

## Discos y Espacio

Knowing where disk space is being used — and running out — can save you from mysterious application crashes.

```bash
# Show disk usage of all mounted filesystems (human-readable)
df -h

# Show disk usage including filesystem type
df -hT

# Show the size of a specific directory
du -sh /var/log

# Show sizes of all items in current directory
du -sh *

# Find the top 10 largest directories
du -h /var | sort -rh | head -10

# Show disk usage one level deep
du -h --max-depth=1 /var

# List all block devices (disks, partitions)
lsblk
lsblk -f     # Include filesystem info

# Mount a filesystem
sudo mount /dev/sdb1 /mnt/data
sudo mount -o ro /dev/sdb1 /mnt/data    # Read-only

# Unmount
sudo umount /mnt/data

# Show currently mounted filesystems
mount | grep "^/dev"
cat /proc/mounts
```

<Tip>
  **Quickly find what's eating your disk space:**
  ```bash
  # Find files larger than 500MB anywhere on the system
  sudo find / -type f -size +500M -exec ls -lh {} \; 2>/dev/null

  # Find largest directories under /var
  sudo du -h /var --max-depth=3 | sort -rh | head -20
  ```
</Tip>

## SSH

SSH is how you connect to remote servers, copy files, and manage infrastructure.

```bash
# Basic SSH connection
ssh user@hostname
ssh user@192.168.1.100

# Connect on a non-standard port
ssh -p 2222 user@hostname

# Connect using a private key
ssh -i ~/.ssh/mykey.pem user@hostname
ssh -i ~/.ssh/id_ed25519 ubuntu@ec2-1-2-3-4.compute.amazonaws.com

# Generate an SSH key pair (Ed25519 is modern and preferred)
ssh-keygen -t ed25519 -C "your@email.com"

# Generate RSA key (4096-bit, for compatibility)
ssh-keygen -t rsa -b 4096 -C "your@email.com"

# Copy your public key to a remote server
ssh-copy-id user@hostname
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@hostname

# Securely copy files between machines
scp file.txt user@hostname:/remote/path/
scp user@hostname:/remote/file.txt ./local/
scp -r ./local-dir/ user@hostname:/remote/path/   # Recursive
scp -i key.pem -r ./dist/ ubuntu@server:/var/www/

# Sync directories (only transfers changes)
rsync -avz ./src/ user@hostname:/var/app/src/
rsync -avz --delete ./src/ user@hostname:/var/app/src/   # Mirror (deletes extra remote files)
rsync -avz -e "ssh -i key.pem" ./deploy/ ubuntu@server:/var/www/

# SSH tunneling (forward a remote port to local)
ssh -L 5432:localhost:5432 user@server    # Access remote Postgres locally
ssh -L 8080:localhost:80 user@server      # Access remote web server on local :8080

# Keep SSH connection alive
ssh -o ServerAliveInterval=60 user@hostname
```

<Tip>
  **Simplify SSH with `~/.ssh/config`:** Stop typing long commands — define aliases in your SSH config file:
  ```text
  Host myserver
      HostName 203.0.113.42
      User ubuntu
      IdentityFile ~/.ssh/mykey.pem
      ServerAliveInterval 60

  Host dev
      HostName 10.0.0.5
      User developer
      Port 2222
  ```
  Now you can just type `ssh myserver` or `ssh dev`. Works with `scp` and `rsync` too.
</Tip>
